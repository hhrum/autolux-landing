# Админка лендинга AutoLux

Документ для дизайна и реализации клиентской части админки.

---

## Цель итерации

Сделать **только визуальную клиентскую часть** админки:

- отдельный route `/admin`;
- мини React-приложение (SPA) внутри этого route;
- без бэкенда, без сохранения в Content Collections / API;
- данные можно захардкодить или читать из моков (те же структуры, что на лендинге);
- UI только под **мобильный телефон**.

Следующие итерации (не сейчас): авторизация, запись в файлы/CMS, превью на сайте, десктоп.

---

## Технический подход

### Route и изоляция от лендинга

- Админка живёт на отдельном route, например `src/pages/admin/[...slug].astro` или `src/pages/admin/index.astro` + client router.
- Внутри — **React SPA** (клиентский роутер: список разделов → формы).
- **Критично:** стили и скрипты админки **не должны попадать на главную** лендинга.
  - React/Tailwind/shadcn подключаются только на `/admin`.
  - Не импортировать админ-бандл и админ-CSS из `Layout.astro` / `index.astro`.
  - Предпочтительно: отдельный entry (остров Astro с `client:only="react"` только на admin-странице) или отдельный Vite-вход для admin SPA.
  - Tailwind для админки — со своим content-scope / отдельным CSS-бандлом, чтобы утилиты админки не раздували и не ломали стили лендинга.

### Стек

| Слой | Выбор |
|---|---|
| UI-фреймворк | React |
| Стили | Tailwind CSS |
| Компоненты | shadcn/ui |
| Markdown-поля | лёгкий MD-редактор (например Milkdown / MDXEditor / `@uiw/react-md-editor` — выбрать один простой) |
| Роутинг внутри SPA | React Router (или аналог) только под `/admin` |
| Данные в этой итерации | моки / статичный JSON, без API |

### Viewport

- Админка **только mobile**: ширина макета ~360–430px.
- На широком экране — либо центрированная «телефонная» колонка, либо просто мобильный layout на всю ширину; **отдельный desktop UI не делать**.
- Навигация: нижний tab bar / stacked screens / «назад» в шапке — как удобнее для телефона.

## Общая структура экранов

```
/admin
 ├─ (опционально) Экран входа — заглушка/мок
 └─ Разделы
     ├─ Бренд и футер
     ├─ Меню
     ├─ Hero
     ├─ Услуги          → список → карточка
     ├─ Тарифы          → список → тариф
     ├─ Преимущества    → список → пункт
     ├─ До / После      → список → кейс
     ├─ Комфорт
     ├─ Отзывы          → список → отзыв
     └─ Контакты
```

Типы экранов:

1. **Список разделов** — входная точка.
2. **Форма одиночного раздела** (Hero, Комфорт, Бренд…).
3. **Список сущностей** + **форма одной сущности** (услуги, тарифы, отзывы…).
4. **Загрузка картинки** — UI превью + «Заменить» (без реального upload API в этой итерации).

Действия в UI (визуально): сохранить, отменить, добавить, удалить, изменить порядок. Сохранение может показывать toast «Сохранено (мок)» без персистенции.

## Базовые типы полей (для UI-kit)

Переиспользуемые контролы на базе shadcn:

| Тип | Назначение | UI |
|---|---|---|
| Текст (одна строка) | названия, цены, ярлыки | `Input` |
| Текст (многострочный) | описания | `Textarea` |
| Markdown | hero-заголовок с акцентом, текст comfort | лёгкий MD-редактор; подсказка: `*акцент*` |
| Телефон | отображение + `tel:` | 1–2 `Input` |
| Ссылка / якорь | CTA, меню, соцсети | `Input` (`#contacts`, `https://…`, `tel:…`) |
| Картинка | логотип, фото, карта, иконки | превью + кнопка заменить |
| Иконка | контакты / преимущества | select или upload SVG |
| Порядок | сортировка | drag или стрелки ↑↓ |
| Переключатель | featured-тариф | `Switch` |
| Repeater | stats, строки прайса, контакты, соцсети | список строк + «Добавить» |
| Пара label + value | статы, строки тарифа | два `Input` в ряд |
| Пара label + href | CTA, пункты меню | два `Input` |
| Шапка секции | badge + title | два `Input` (общий паттерн) |

## Вне скоупа этой итерации

- Реальное сохранение в Content Collections / Git / API
- Авторизация и роли
- SEO title/description
- Десктоп-адаптив админки
- Live-превью лендинга рядом с формой
- Мультиязычность, история версий

---

## Критерии приёмки (visual / client)

- [ ] `/admin` открывается отдельно от главной
- [ ] CSS/JS админки не подключены на `/`
- [ ] Все перечисленные разделы доступны с телефона
- [ ] Списки сущностей: просмотр, переход в форму, UI добавления/удаления/порядка
- [ ] Поля MD (hero title, comfort) редактируются через лёгкий MD-редактор
- [ ] Картинки: превью и кнопка «заменить» (мок)
- [ ] Стек: React + Tailwind + shadcn + MD-редактор
- [ ] Layout рассчитан только на mobile
